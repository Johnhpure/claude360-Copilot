# Claude Plan — Claude 生成的文档目录

> 本目录存放 **Claude** 为 Claude360 Copilot 二次开发生成的全部文档，与 `../codex-plan/`（Codex 的产出）并列、互不混淆。

## 目录结构

| 子目录 | 内容 |
| --- | --- |
| `功能说明文档/` | 对原项目（Kun）全部功能的最小颗粒度分析说明书：1 篇总纲 `README.md` + 01–07 共 7 篇分章（运行时核心 / 工具系统 / 服务端 / GUI 主进程 / 对话与计划 / Write 写作 / 自动化设置）。这是改造前基线文档，P2 后会有部分能力被删除 |
| `specs/` | 项目级设计规格。`2026-06-30-claude360-copilot-总体架构-design.md` = 二次开发总体架构规划（决策汇总、二元凭据模型、P0–P5 子项目分解、白牌化分层、实施顺序） |
| `plans/` | 子项目实施计划。`2026-06-30-p2-移除形象工坊.md` = M1·P2 逐 Task 计划；`2026-06-30-p0-白牌化.md` = M1·P0 白牌化逐 Task 计划（含命名映射表与 OPEN 依赖）；`2026-06-30-p1-中转站接入地基.md` = M2·P1 逐 Task 计划（newapi `/api/cli/*` 契约已核实，含网关模块/登录/凭据/供应商收敛/模型来源） |

## 阅读顺序建议

1. 先读 `功能说明文档/README.md` 了解原项目能力全貌
2. 再读 `specs/` 总体架构规划掌握改造路线
3. 最后按 `plans/` 逐个子项目实施；M1 推荐顺序为 `P2 移除形象工坊 → P0 白牌化 → P1 中转站接入地基`

## 约定

后续 Claude 生成的所有设计/计划文档统一写入本目录（`specs/` 与 `plans/`），不与 `codex-plan/` 混放。
