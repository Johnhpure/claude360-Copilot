# 03 · 运行时核心：服务端与运行时子系统

> 范围：`kun/src/server`、`services`、`hooks`、`delegation`、`review`、`skills`、`memory`、`quality`、`config`、`cli`、`domain`、`prompt`、`telemetry`
> 参考：`kun/README.zh-CN.md`、`docs/kun-hooks.md`、`docs/KUN_CONFIG.md`

Kun 是 Electron AI Agent 桌面应用的本地 Agent 运行时，GUI（渲染进程）通过本地 HTTP + SSE 与之通信。下文按子系统逐一展开到最小颗粒度。

---

## 一、HTTP/SSE 服务端基础设施（server/）

### 1.1 功能
提供零依赖、最小化的本地 HTTP 服务器与路由器，把 GUI 的 REST/SSE 请求分发到各业务服务。所有 `/v1/*` 路由经 Bearer Token 鉴权，`/health` 不鉴权。

### 1.2 请求生命周期
1. **`node-http-server.ts`**：Node 原生 `http.createServer`，`toFetchRequest` 把 IncomingMessage 转 Web `Request`（非 GET/HEAD 用 `Readable.toWeb` 包请求体、`duplex:'half'`），`writeFetchResponse` 流式写回（支持 SSE 长连接），异常统一 500。
2. **`http-server.ts`（dispatchRequest）**：解析 URL → `router.match` → 无匹配 404 → 内部 `JsonResponse` 转 Web Response。
3. **`router.ts`（Router）**：极简路由器，按注册顺序匹配，支持 `:param` 占位符，段数须完全相等。
4. **`auth.ts`**：`bearerToken` 解析；`isAuthorized` 在 `insecure=true` 放行否则要求 token 严格相等。
5. **`response.ts`** / **`read-json-body.ts`**：`jsonResponse` 输出 JSON；`readJsonBody` 空体返回 `{}`，解析失败 400。
6. **`sse.ts`（encodeSseEvent）**：编码 `id: {seq}\nevent: {kind}\ndata: {JSON}\n\n`，`id` 用事件 seq 支持 `Last-Event-ID` 续传。
7. **`runtime-error.ts`（ERRORS）**：统一错误工厂，固定 code+状态码：unauthorized(401)、forbidden(403)、notFound(404)、validation(400)、conflict(409)、notImplemented(501)、unavailable(503)、internal(500)。
8. **`event-loop-monitor.ts`**：`unref` 的 setInterval 心跳（默认 1s），晚 ≥2000ms 打印 `event loop stalled`，区分 CPU 饥饿与硬死锁（issue #621）。

### 1.3 SSE 事件流机制（routes/events.ts `buildEventStreamResponse`）
`GET /v1/threads/{id}/events` 是整套实时 UI 支柱：
- **断点续传起点**：`since_seq`（query）或 `Last-Event-ID`（header）取较大者。
- **先回放后订阅**：`highestSeq` → `since_seq < highestSeq` 则 `loadEventsSince` 回放积压 → `eventBus.subscribe` 订阅实时。
- **逐连接去重**：`lastDeliveredSeq` 高水位线，重叠事件只投递一次（recorder「先持久化后发布」）。
- **心跳**：每 15s 发 `heartbeat` 帧，复用 `lastDeliveredSeq` 而非分配新 seq（避免重启后 seq 倒退）。
- **响应头**：`text/event-stream`、`no-cache, no-transform`、`keep-alive`。

### 1.4 组合根（runtime-factory.ts）—— 运行时如何装配
`createKunServeRuntime(options)` 是 serve 模式唯一把具体 adapter 接到 port 的地方，全部构造器注入：
- 建 dataDir、`InMemoryEventBus`、持久化存储（默认 `hybrid`：`HybridThreadStore`(SQLite 索引)+`HybridSessionStore`(JSONL)，或 `file` 后端）。
- 建 ApprovalGate、UserInputGate、WorkspaceInspector、UsageService、InflightTracker、SteeringQueue、ContextCompactor、RuntimeEventRecorder。
- **不可变前缀** `createImmutablePrefix({systemPrompt: KUN_SYSTEM_PROMPT, pinnedConstraints:[…]})`。
- 模型客户端：`CompatModelClient`（默认）+ 每个 `kind:'http'` provider 独立客户端，`MultiProviderModelClient` 按 providerId 路由；`kind:'agent-sdk'` 由 `createAgentSdkRuntime` 接管整轮。
- 并行 I/O：MCP 工具、SkillRuntime、usage carryover 回种。
- 建 TurnService、BackgroundShellRuntime、ReviewService、全部工具 provider；computer_use 故意不进 baseToolProviders。
- Hooks：内置 hook 在前，配置 hook 在后。
- 两套 CapabilityRegistry：childRegistry（子 agent）+ registry（主 agent 加 computer_use/goal/todo/delegation）。
- DelegationRuntime（启用 subagents 时）：FileDelegationStore 存 `child-runs/`，子 agent 作为隐藏 side 线程持久化，完成时回灌父线程用量。
- AgentLoop 注入全部依赖 + `onPlanWritten`（同步 todos）。
- `startKunServe`：listen 后后台清扫——`reconcileOrphanedTurns`（残留 queued/running turn 标 failed）+ `resumeInterruptedGoals` + `reconcileOrphanedChildRuns`，均不阻塞 readiness。

### 1.5 ServerRuntime 依赖契约（routes/server-runtime.ts）
聚合 threadService/turnService/usageService/reviewService、eventBus/sessionStore、approvalGate/userInputGate/workspaceInspector/toolHost、attachmentStore/memoryStore/delegationRuntime/backgroundShellRuntime、modelClient/defaultModel/roles/immutablePrefix，以及 runTurn/runReview/resumeInterruptedGoals、runtimeToken/insecure/allocateSeq/info()/shutdown 等。可选字段让测试脚手架按需省略。

## 二、业务服务层（services/）

### 2.1 ThreadService（thread-service.ts）
- **功能**：线程 CRUD、fork、resume-session、goal、todos、与 GUI plan 的 todo 同步，是 thread 领域唯一变更入口，每次变更 `events.record(...)`。
- **要点**：`list` 默认隐藏 side 线程；`create` 始终先推进 id 生成器防碰撞；`update` 中 `costBudgetUsd===null` 清预算+告警；`setTodos` 去重 + 至多一个 in_progress + 改动 plan 源 todo 时回写工作区 plan markdown 勾选框；`fork` 快照语义克隆 turns（side 对在飞 turn 只留用户 prompt 标 aborted，fork 收尾为 completed），默认强制 agent 模式；`resumeSession` 从旧 items 重建 turns。

### 2.2 TurnService（turn-service.ts）
- **功能**：turn 的 start/finish/abort/steer/compact/rewind，唯一发出 turn 生命周期事件的地方。
- **要点**：`startTurn` 建 turn + 用户消息 item、线程置 running、建 AbortController；`steerTurn` enqueue + 发 `turn_steered`；`interruptTurn` abort + 清 steering（discard 丢非用户 item）；`compact` 仅 `replacedTokens>0` 才发压缩事件，model 模式额外 `summarizeCompactionWithModel`；`reconcileOrphanedTurns` 重启清扫残留 turn（含 side 线程，否则委派子 agent 永久卡死）；`applyItem`/`updateItem` 写 session+thread+发 item 事件；`upsertThread` 每线程串行队列防并发覆盖。

### 2.3 UsageService（usage-service.ts）+ telemetry
- **功能**：协调用量计数与缓存遥测。`record` 累加返回快照、`seedThread`（重启回种）、`forThread`/`total`/`cacheSnapshot`。
- **要点**：底层 `UsageCounter`（per-thread token/缓存命中/成本/turns）+ `CacheTelemetry`（hits/misses/writes/invalidations + hitRate）；`withCacheDiagnostics` 对比前后签名算命中率与 miss 原因；用量聚合端点 `group_by=runtime/thread/day/model`，日/模型分组校验时区与日期窗口（最多 `MAX_DAILY_USAGE_DAYS=370`），优先用索引否则 JSONL 回放叠加 live 增量。

### 2.4 ReviewService（review-service.ts）
- **功能**：在完全隔离的内存运行时跑只读代码审查，结构化 JSON 写回主线程 review item。
- **要点**：`runReview` 拿父 turn abort signal → `resolveReviewTargetPrompt` 构造 prompt → `runIsolatedReviewer` 用全套 InMemory 存储 + 只读工具 + 专用 `KUN_REVIEW_PROMPT` 新建 AgentLoop 在临时 child thread 跑一轮 → 汇总 → `parseReviewOutput` → `renderReviewOutput` → 成功 updateItem completed。审查模型优先级：请求 → thread.model → defaultModel；reasoningEffort 来自 `roles.codeReviewReasoningEffort`。

### 2.5 RuntimeEventRecorder（runtime-event-recorder.ts）
- **功能**：统一盖序号/时间戳 → Zod 校验公开契约 → 持久化（供 SSE 回放）→ 发布到 event bus。
- **要点**：`nextSeq` 每线程读一次持久高水位并缓存，同步发号保证单调；**「先持久化后发布」是 load-bearing 不变量**（否则事件落在「读积压」与「订阅总线」之间永久丢失）。

### 2.6 LlmDebugRecorder（llm-debug-recorder.ts）
- **功能**：固定容量 `CAPACITY=25` 纯内存环形缓冲，记录最近 LLM 轮次（请求体、原始流式输出、provider/model/脱敏 url/耗时），重启即清，绝不落盘，供 `/v1/debug/llm-rounds`。

### 2.7 后台 Shell 子系统（background-shell-*.ts）
- **`background-shell-runtime.ts`**：`bashHooks()` 提供 onSessionStarted/Updated/Settled 回调发事件；**`handleSessionSettled` 在分离式会话成功完成时 `notifyAgent`**——有运行中 turn 则 `steerTurn` 注入完成通知，否则 `startTurn`+`runTurn` 起一轮把通知喂模型（后台命令跑完自动唤醒 agent）。
- **`background-shell-output.ts`**：日志落盘 `{dataDir}/threads/{threadId}/background-shells/{sessionId}.output`，默认截断 10000 字符；`isBackgroundShellOutputPath` 校验路径防越权读。
- **`background-shell-notice.ts`**：用 `<background_shell_completed>` XML 标签格式化喂模型的完成通知。

## 三、Hook 子系统（hooks/）

### 3.1 功能
在 agent loop 与工具宿主各阶段插入用户/内置逻辑，可拒绝动作、改写参数/输出、注入上下文。

### 3.2 生命周期阶段（HOOK_PHASES）

| 阶段 | 类别 | 触发点 | 能力 |
|---|---|---|---|
| `PreToolUse` | 工具 | 每次工具调用前 | deny 阻断；allow 跳过审批；arguments 改写参数（链式） |
| `PostToolUse` | 工具 | 每次工具调用后 | output 改写结果；isError 标错（链式） |
| `UserPromptSubmit` | 生命周期 | 首次模型调用前 | deny 失败整 turn；additionalContext 注入持久上下文；**崩溃 fail-open** |
| `TurnStart` | 生命周期 | turn 开始 | 仅观察 |
| `TurnEnd` | 生命周期 | turn 结束 | 仅观察 |
| `PreCompact` | 生命周期 | 压缩前 | 仅观察 |

### 3.3 机制
- **匹配**：`hookMatchesTool` 按 `toolNames`（精确白名单）或 `matcher`（glob：`*` 通配、`|` 交替）；皆空则匹配所有。
- **命令 hook 协议**：`spawn(command, {shell:true})`，invocation 作 JSON 写 stdin；**exit 0**→stdout 解析 HookResult；**exit 2**（`HOOK_BLOCKING_EXIT_CODE`）→阻断，stderr 为原因；其它退出码→非阻断警告；超时默认 60000ms 杀进程树。
- **配置**：`HookCommandConfigSchema`（shell hook）、`HookWorkflowConfigSchema`（POST 到 WorkflowRuntime 跑 GUI Loop 工作流，mode observe/block/rewrite）。

### 3.4 内置 hook（hooks/builtins/）
- **`design-quality-hook.ts`**：唯一内置 hook，PostToolUse 阶段、仅对 write/edit 的前端文件触发，调 `detectFrontend` 检测设计「AI 痕迹」，以 `design_quality_review` 块折进工具结果让模型下一轮自我纠正。**纯顾问性**：从不标错/阻断。

## 四、委派子系统（delegation/）

### 4.1 功能
让主 agent 通过 `delegate_task` 把独立工作单元派给子 agent（可并行、可后台分离），子 agent 隔离上下文运行，结果回灌父线程。

### 4.2 内置 profile（builtin-profiles.ts）

| profile | toolPolicy | 说明 |
|---|---|---|
| `general` | `inherit` | 通用代理，继承主 agent 全部工具（todo 除外），**默认 profile** |
| `explore` | `readOnly` | 快速只读探索，不改文件 |
| `design-reviewer` | `readOnly` | 只读前端设计审查者 |
| `over-engineering-reviewer` | `readOnly` | 只读过度设计审查者（delete/stdlib/native/yagni/shrink） |

`mergeBuiltinSubagentProfiles` 逐 id 深合并（内置为底，用户字段优先），`defaultProfile` 兜底 general。

### 4.3 工作区 agent 覆盖（workspace-agents.ts）
`loadWorkspaceAgentProfiles` 加载 `<workspace>/.kun/agents/*.md`，三层覆盖 **internal < GUI < workspace**；Markdown frontmatter（自研 YAML 解析）支持 id/name/mode/model/toolPolicy/allowedTools/blockedTools/blockedMcpServers/blockedSkills 等，body 即 systemPrompt；坏文件静默丢弃。

### 4.4 委派运行时（delegation-runtime.ts）
- **`runChild`**：解析 profile → model/systemPrompt/工具策略；**预算保护** `ensureSeeded` + `reserveChild`（`maxChildRuns` 上限）；建 ChildRunRecord 持久化；**同步路径** `acquireSlot`（FIFO 并发槽，`maxParallel` 上限）→ running → executor；**分离式路径**立即返回 queued，后台跑，可 `abortChild` 取消。
- **`reconcileOrphanedChildRuns`**：重启清扫残留记录为 failed。
- **`recordChildEvent`**：把子 run 状态映射为父线程 turn 事件，携带 childId/model/profile/toolPolicy/prefixReused/totalTokens/cacheHitRate/cost，驱动 GUI 子 agent 卡片。

### 4.5 子 agent 执行器（child-agent-executor.ts）
- 默认复用主运行时 stores+event bus（作为隐藏 side 线程持久化，可实时流式到 GUI）。
- **工具门控（最具体优先）**：显式 allowedTools > readOnly 限投查工具 > inherit；叠加 blockedTools/blockedMcpServers（`mcp:<serverId>` 级）/blockedSkills（只移除不升级）。子 agent 跑在父线程 approvalPolicy/sandboxMode 下（非权限提升）。
- **前缀策略**：自定义 systemPrompt 时增广基前缀保 prompt 缓存；preamble 放 prompt body 而非 system prompt。
- 只有致命错误才标 failed，可恢复工具错误只记 warning。

## 五、代码审查子系统（review/）

### 5.1 审查目标解析（git-review-target.ts）
按 `ReviewTarget.kind`（默认 diff 上限 256KB，超限 UTF-8 安全截断）：`custom`（自定义指令）、`uncommittedChanges`（并行 status/staged/unstaged/untracked）、`baseBranch`（merge-base + diff）、`commit`（show）。`runGit` 用 execFile（超时 10s）。

### 5.2 审查 system prompt（review-prompt.ts，KUN_REVIEW_PROMPT）
固定英文：senior code reviewer，只找该变更引入的离散可执行 bug（正确性/安全/性能/并发/数据丢失/API 契约回归/缺失测试），不报风格/命名/投机性；只读工具绝不编辑；每条 finding 单 bug、最小行范围、绝对路径、priority 0-3、confidenceScore 0-1；**只返回 JSON**。

### 5.3 审查输出解析与渲染（review-output.ts）
`parseReviewOutput` 先 JSON.parse 失败则 `firstJsonObject` 手写括号深度扫描；兼容 camelCase/snake_case；`renderReviewOutput` 渲染为人类可读文本。HTTP 入口 `routes/review.ts startReview` startTurn + makeReviewItem(running) 返回 202。

## 六、技能子系统（skills/skill-runtime.ts）

- **功能**：发现/匹配/注入工作区与全局技能（SKILL.md/manifest），按 token 预算注入目录与激活指令，支持 `load_skill` 按需拉取。
- **机制**：根目录 `.agents/skills`、`.claude/skills`、`.codex/skills`、`skills` + config roots；**`resolveTurn`** 核心：filterBlockedSkills → renderCatalogInstruction（`catalogBudgetBytes=8000`）→ matchSkills（commands/promptPatterns/fileTypes 评分）→ 取前 `activeLimit=3` 激活 → buildInjection（`instructionBudgetBytes=24000`）→ 算 blockedToolNames（未激活技能声明的工具被屏蔽）。**workspace-local 技能走 resolveTurn 注入而非进不可变前缀**（保护缓存）。`loadSkillById` 永不抛错（错误以 payload 返回）。

## 七、记忆子系统（memory/memory-store.ts，FileMemoryStore）

- **功能**：长期记忆 CRUD + 按查询语义检索注入，每条按文件存储。
- **机制**：作用域 user（身份事实，无条件全注入）/workspace/project；CRUD 软删（墓碑），atomicWriteFile；update/delete 带 workspace 作用域校验；**`retrieve`**：user 作用域无条件全注入，workspace/project 走 `scoreMemory`（`ngrams` 双语 n-gram：ASCII trigram + CJK bigram）按分取 limit。store 缺失时 503。

## 八、设计质量子系统（quality/）

- **功能**：零依赖、基于源码文本（非 DOM）的前端设计质量检测器，被内置 PostToolUse hook 调用，找「AI 生成痕迹（slop）」与 craft 问题。
- **机制**：`detectFrontend(source, options)` 纯同步永不抛错，按扩展名门控（html/css/scss/jsx/tsx/vue/svelte/svg），按 strictness（relaxed/standard/strict）过滤规则，去重排序截到 `maxFindings`（默认 12）；category 三类 slop/quality/drift；`DESIGN_RULES` 规则注册表（算法重实现自公开 lint 规则）。

## 九、配置与密钥脱敏（config/）

### 9.1 kun-config（kun-config.ts）
顶层 `KunConfigSchema`（`.strict()`）：serve/models/contextCompaction/runtime/roles/capabilities/hooks/quality。关键：
- **KunServeConfigSchema**：host/port/dataDir/runtimeToken/apiKey/baseUrl/modelProxyUrl/endpointFormat/model/approvalPolicy/sandboxMode/tokenEconomyMode/insecure/storage/**providers**（per-providerId HTTP 凭据，`kind:'http'|'agent-sdk'`）。
- **RolesConfigSchema**：`smallModel` 为廉价一次性调用默认，各角色（title/summary/codeReview）可覆盖 model/providerId/reasoningEffort；压缩故意不在此（复用主模型保缓存）。
- ContextCompaction/RuntimeTuning/Quality/TokenEconomy/Storage 各子 schema；默认模型 `deepseek-v4-pro`。
- 加载：`readKunConfigFile`（JSON.parse + safeParse）、`kunConfigPathForDataDir`（`{dataDir}/config.json`）、`expandHomePath`。

### 9.2 密钥脱敏（secret-redaction.ts）
`redactSecrets` 递归遍历：键匹配 `api[-_]?key|authorization|bearer|client[-_]?secret|password|secret|token` 的值换 `<redacted>`；字符串值额外 `redactSecretText` 替换 `authorization/bearer xxx` 模式。用于 `/v1/runtime/tools` 诊断输出防凭据泄露。

## 十、CLI 子系统（cli/）

### 10.1 命令与入口
- **`serve-entry.ts`**：进程主入口。`splitKunCliCommand` 分发 serve/run/chat/exec/help。serve 路径：parseServeOptionsSafe → installServeCrashHandlers → startKunServe → selfVerifyHealth（5s 内轮询 /health）→ 打印 **`KUN_READY {json}`** 握手行（GUI 据此识别就绪）→ startEventLoopMonitor → 等 SIGTERM/SIGINT 优雅关闭。
- **`agent-cli.ts`**：`run`（一次性单轮，可 --json）/`chat`（行式终端聊天）/`exec`（--list-tools 或 `exec <tool> --args <json>` 调工具）。
- **`serve.ts`** / **`cli-options.ts`**：argv + env + config 三级合并；默认端口 `DEFAULT_SERVE_PORT=18899`；`ServeOptionsSchema` 校验。
- **`serve-crash-handlers.ts`**：`uncaughtException`→优雅关闭 + 非零退出（让 GUI 监督者重启）；`unhandledRejection`→只记日志不退出（#639）。

## 十二、提示词与遥测

### 12.1 Kun 系统提示词（prompt/kun-system-prompt.ts，KUN_SYSTEM_PROMPT）
**刻意字节稳定**的英文操作契约，置于每个 Kun 模型请求最前供 prompt 缓存跨 Code/Write/Claw/plan/工具续跑复用。分节：核心身份（保留用户意图尤其负向约束、小而连贯改动、行动前读现状）、GUI 契约、编码行为、工具行为、记忆行为（写前须用户同意）、缓存行为（稳定前缀字节稳定）、响应风格、安全质量。**禁止随意重排/个性化此前缀**。

### 12.2 遥测（telemetry/）
- `usage-counter.ts`：per-thread 用量累加器，UsageService 底层。
- `cache-telemetry.ts`：缓存命中遥测累加器（hits/misses/writes/invalidations + hitRate），GUI「缓存命中率」徽章真理来源。
