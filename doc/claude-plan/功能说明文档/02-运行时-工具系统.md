# 02 · 运行时核心：工具系统（Tools & Capability Providers）

> 范围：`kun/src/adapters/tool/`（全部）+ 装配入口 `kun/src/server/runtime-factory.ts`

Kun 运行时把模型可调用的全部能力抽象为「工具（Tool）」，由若干 Provider 提供，统一经 `CapabilityRegistry` 装配进 `LocalToolHost`，并在执行时叠加沙箱、审批、读前置守卫、限流、生命周期 Hook 等多层闸门。本章按「基础设施 → 文件类 → 执行类 → 代码智能 → 规划类 → 扩展 Provider」顺序，对每个工具做最小颗粒度说明，最后单列「工具注册与能力发现机制」。

所有工具统一遵循 `LocalTool` 接口（`local-tool-host.ts`）：

- **字段**：`name`、`description`（模型可见）、`inputSchema`、`toolKind`（`tool_call`/`command_execution`/`file_change`）、`policy`（`auto`/`on-request`/`suggest`/`never`/`untrusted`）、可选 `shouldAdvertise(context)`、`execute(args, context, onUpdate)`。
- **policy 语义**：`auto` 不询问；`on-request`/`suggest` 默认询问；`never` 直接拒绝；`untrusted` 除非命中 allow-list 否则询问。
- **toolKind 语义**：`file_change` 与 `command_execution` 受沙箱模式单独管控。

## 一、基础设施

### 1. capability-registry（能力注册表）

- **文件**：`capability-registry.ts`
- **功能**：以 Provider 为单位登记工具，提供 `listTools`（列出）与 `resolveTool`（解析）两套能力发现 API。
- **细节**：
  - 注册时对**重复 Provider id** 和**重复工具名**抛错。
  - `listTools(context)` 逐层过滤：① Provider 可用性（`enabled && available` + allow/block）→ ② 工具级 allow/block → ③ **Plan 模式白名单**（仅放行 `read/grep/find/ls/create_plan/user_input/request_user_input`）→ ④ 沙箱可见性 → ⑤ 工具自身 `shouldAdvertise`。
  - `resolveTool` 执行前再次复核（广告层 + 执行层双重门禁）。
  - `diagnostics()` 输出各 Provider 策略快照。

### 2. local-tool-host（默认工具宿主）

- **文件**：`local-tool-host.ts`（`LocalToolHost`，`id='local'`）
- **执行管线（execute 闸门顺序）**：
  1. abort 检查；2. `resolveTool`，`policy==='never'` 拒绝；3. **沙箱阻断** `sandboxBlockForTool`；4. **PreToolUse Hook**（可改参数/拒绝/免审批）；5. **读前置守卫** `ReadTracker.validateBeforeTool`；6. **运行时策略阻断**（`approvalPolicy==='never'` 时非交互工具一律拒绝）；7. **审批判定** `requiresApproval`；8. 执行 `tool.execute`，流式 `onUpdate` 包装为 `running`；9. **执行异常隔离**（转 `tool_execution_failed`，不杀 turn）；10. **PostToolUse Hook** → 限流归一化 → `ReadTracker.observeToolResult`。
- **内置**：`echo`（冒烟）、`user_input`/`request_user_input`（结构化提问，交互门类不受审批/沙箱限制）。`buildDefaultLocalTools()` = 内置工具 + echo + user_input + create_plan。

### 3. builtin-tools / builtin-tool-types / builtin-tool-operations

- **`builtin-tools.ts`**：工厂总线，`createBuiltinLocalTool(name, opts)` 分发 read/bash/edit/write/grep/find/ls/lsp/verify_changes；提供全集/coding/read-only 套装。
- **`builtin-tool-types.ts`**：常量——`DEFAULT_BASH_TIMEOUT_SECONDS=120`、`DEFAULT_SEARCH_LIMIT=100`、`DEFAULT_LIST_LIMIT=500`、`DEFAULT_FIND_LIMIT=1000`、`DEFAULT_IMAGE_MAX_DIMENSION=2000`、`DEFAULT_IMAGE_MAX_BASE64_BYTES≈4.5MB`、`fd`/`rg` 候选路径。
- **`builtin-tool-operations.ts`**：默认 I/O。图片缩放 `resizeImageWithSips` 依赖 macOS `sips`，按 2000px 上限与 4.5MB 字节上限反复缩小（每轮 ×0.75）。

### 4. builtin-tool-utils（公共底座）

- **文件**：`builtin-tool-utils.ts`
- **能力**：`resolveWorkspacePath`（realpath + 符号链接逐段解析的越界防护，`danger-full-access` 放开边界，悬空符号链接跟随 target 再判定）；`isBinaryBuffer`（前 4096 字节含 `0x00`）；`detectImageMimeType`（魔数解析）；跨平台 shell 配置（Win `pwsh→powershell→bash→cmd`，POSIX `bash→sh`）；`terminateSpawnTree`（Win `taskkill /T /F`，POSIX `kill(-pid)`）；`globToRegExp`；`withToolBoundary`。

### 5. truncate（截断算法）

- **文件**：`truncate.ts`，`DEFAULT_MAX_LINES=2000`、`DEFAULT_MAX_BYTES=50KB`
- **细节**：`truncateHead`（read 用）/`truncateTail`（bash 用）双向，按行数+字节双上限；记录 `truncatedBy`、`firstLineExceedsLimit`、`lastLinePartial`（UTF-8 续字节边界对齐避免乱码）。

### 6. output-accumulator（流式输出累加器）

- **文件**：`output-accumulator.ts`
- **细节**：bash/后台 shell 实时输出累积，编码自动嗅探（UTF-8/UTF-16LE BOM + 启发式）；内存保留约 2×maxBytes 尾部，超阈值把原始字节落临时文件（`kun-bash-*.log`）；`snapshot` 返回可见内容 + 截断元数据 + 完整输出路径。

### 7. read-tracker（读前置守卫）

- **文件**：`read-tracker.ts`
- **细节**：按 `threadId → 绝对路径` 缓存 read 结果；`validateBeforeTool` 对 edit/edit_file/apply_patch 生效——从未读过目标文件则阻断（`read_before_edit_required`）；跨 turn 的读仍算数；运行时默认开启。

### 8. file-mutation-queue（文件写串行化）

- **文件**：`file-mutation-queue.ts`
- **细节**：`withFileMutationQueue(path, fn)` 进程内按 realpath 串行 + 跨进程文件锁（`tmpdir/kun-file-mutation-locks/<sha256>.lock`，轮询 25ms、最长 60s），自动清理死进程锁与无主超时锁（>10 分钟）。被 write/edit/create_plan 复用。

### 9. tool-rate-limit（限流归一化）

- **文件**：`tool-rate-limit.ts`
- **细节**：PostToolUse 后扫描输出，正则匹配 `rate limit/too many requests/quota exceeded/429`，解析 `retry-after` 换算秒，归一化为 `{code:'rate_limited', retry_after_seconds, ...}` 并标 isError。

### 10. tool-result-image（工具结果图片路由）

- **文件**：`kun/src/loop/tool-result-image.ts`（loop 层，被工具结果消费）
- **细节**：仅 `kind∈{image, computer_screenshot}` 为模型可见图（`generate_image` 排除）；每张按 1200 token 估算；`capToolResultImages` 仅保留最近 N 张，旧的折叠占位。

## 二、文件类工具

### 11. read（读取文件）

- **标识/文件**：`read` / `builtin-read-tool.ts`，policy=`auto`
- **输入**：`path`（必填）、`offset`（1 起始行）、`limit`。
- **细节**：越界校验后读字节。**图片**：默认 `autoResizeImages=true`，用 `sips` 缩放到内联上限（给出缩放倍数提示便于坐标换算），无法缩放则省略图像数据。**二进制**：非图片二进制报错。**文本截断**：CRLF→LF，按 offset/limit 切片经 `truncateHead`（2000 行/50KB），超限给续读提示；单行超字节上限提示改用 bash。**分类标注**：识别 SKILL.md（skill）、AGENTS.md/CLAUDE.md（resource）、README/docs/examples（docs）。

### 12. write（创建/覆盖文件）

- **标识/文件**：`write` / `builtin-file-tools.ts`，policy=`on-request`，toolKind=`file_change`
- **输入**：`path`、`content`。
- **细节**：`assertCanWritePath` 沙箱校验 → `withFileMutationQueue` 串行 → 递归建目录写 UTF-8，返回 `bytes_written`。截断参数（`__raw`）给「拆成多次小 edit」引导。

### 13. edit（精确文本替换，含 diff 机制）

- **标识/文件**：`edit` / `builtin-file-tools.ts` + `edit-diff.ts`，policy=`on-request`，toolKind=`file_change`
- **输入**：`path`；`oldText`+`newText` 单条，或 `edits[]` 多处不相交编辑。
- **diff/匹配机制**：读文件后 `stripBom` + `detectLineEnding`（保留原换行）+ `normalizeToLF`；**模糊匹配 `fuzzyFindText`**：先精确 `indexOf`，失败则 NFKC + 行尾 trim + 智能引号/连字符/空格统一后再匹配；**唯一性校验**：多处出现报「需更多上下文」，空/未找到/无变化/区间重叠各有明确错误；**应用顺序**：按 matchIndex 从后往前替换；**输出 diff**：`generateDisplayDiff`（带行号、`±` 前缀、±4 行上下文、长段折叠）+ `generateUnifiedPatch`；写回 `restoreLineEndings` 还原 CRLF/BOM。

### 14-16. ls / find / grep

- **ls**（`builtin-search-tools.ts`，policy=`auto`）：`path`（默认 `.`）、`limit`（默认 500）；条目字母序，目录标 `name/`，返回 entries/names/truncated。
- **find**（policy=`auto`）：`pattern`、`path`、`limit`（默认 1000）；**后端三级回退** `fd → rg --files → 自实现 globToRegExp`；不含 `/` 的 pattern 自动加 `**/` 前缀；`backend` 标明实际后端。
- **grep**（policy=`auto`）：`pattern`、`path`、`glob`、`ignoreCase`、`literal`、`context`、`limit`（默认 100）；优先 `rg` 否则自扫描；二进制跳过；返回每条 path/line/column/text + 可选上下文。

## 三、执行类工具

### 17. bash（执行 shell 命令，含后台 shell）

- **标识/文件**：`bash` / `builtin-bash-tool.ts`，policy=`on-request`，toolKind=`command_execution`
- **输入**：`command`、`timeout`（秒，默认 120）、`background`（默认 false）。
- **细节**：
  - **同步模式**：宿主 shell 在 workspace 启动 detached 进程，stdout/stderr 合并经 `OutputAccumulator`（2000 行/50KB，超限落盘），约 100ms 节流推送 partial；超时/中止杀进程组；非 0 退出标 isError；返回 `full_output_path`。
  - **后台模式**：分配 8 字符 session_id，进程持续到 turn 结束之后，输出落盘（需 dataDir），经 `onSessionStarted/Updated/Settled` 通知；完成后保留 10 分钟。状态机 `running/completed/stopped/failed`。

### 18. background_shell（后台会话管理）

- **标识/文件**：`background_shell` / `background-shell-tool.ts`，policy=`auto`
- **输入**：`action`（list/read/poll/write/stop）、`session_id`、`yield_seconds`（1–60）、`include_finished`、`thread_only`、`input`。
- **细节**：`list` 默认仅本线程运行中；`read` 非阻塞快照；`poll` 阻塞至多 yield_seconds；`write` 写 stdin 后 poll；`stop` SIGTERM 进程组（1s 宽限）。session_id 须匹配 `^[a-z0-9]{8}$`。

### 19. sandbox-policy（沙箱策略规则）

- **文件**：`sandbox-policy.ts`
- **规则**：`danger-full-access` 全放行；`read-only` 阻断全部 file_change/command_execution；`workspace-write` 允许进程内 file_change 但写路径须在工作区内；`external-sandbox` 写被拒；`user_input/request_user_input` 任何模式都放行；`assertCanWritePath` 被 write/edit/create_plan 调用。

### 20. verify_changes（变更验收）

- **标识/文件**：`verify_changes` / `builtin-verify-tool.ts`，policy=`on-request`，toolKind=`command_execution`
- **输入**：`scope`（focused/full）、`timeout`（1–600，默认 180）。
- **细节**：用 git diff 收集变更文件 → 定位 package 根 → **focused** 跑相邻 Vitest + typecheck，**full** 追加 lint + build；自动探测包管理器（pnpm/yarn/bun/npm）；单条失败即停；输出上限 24000 字符；无变更或无脚本时 skipped。

## 四、代码智能

### 21. lsp（语言服务器查询）

- **标识/文件**：`lsp` / `builtin-lsp-tool.ts`，policy=`auto`
- **输入**：`operation`、`filePath`、`line`/`character`（1 起始）、`query`。
- **操作集（全只读）**：`goToDefinition`、`findReferences`、`hover`、`documentSymbol`、`workspaceSymbol`、`goToImplementation`、`getDiagnostics`。
- **细节**：1 基位置转 0 基；除 workspaceSymbol 外先 didOpen；`simplifyResult` 精简 URI/位置/SymbolKind 名称；无匹配服务器返回带安装提示的错误。

### 22. lsp-servers（语言服务器注册表）

- **支持语言**：TypeScript/JavaScript（`typescript-language-server`）、Python（`basedpyright→pyright→pylsp`）、Rust（`rust-analyzer`）、Go（`gopls`）、C/C++（`clangd`）、JSON（`vscode-json-language-server`）、YAML（`yaml-language-server`）。
- **细节**：优先用工作区 `node_modules/.bin` 本地二进制再回退 PATH；每语言给 installHint 与 languageId；`probeServerBinary` 用 which/where 探测（3s 超时）。

### 23. lsp-client（最小 LSP 客户端）

- **细节**：JSON-RPC 2.0 over stdio 查询型客户端；会话按 `workspaceRoot::serverKey` 引用计数复用，末位释放 30s 后杀进程；请求 30s 超时；处理 `workspace/configuration`、`registerCapability`、`diagnostic/refresh`；失败服务器进 5 分钟冷却；`process.on('exit')` SIGKILL 防孤儿。

### 24. lsp-notifications（LSP 通知处理）

- **细节**：`publishDiagnostics` 按 URI 存缓存；`window/logMessage`/`$/logTrace` 按 type 映射到 console。

## 五、规划类

### 25. create_plan（GUI 计划写入）

- **标识/文件**：`create_plan` / `create-plan-tool.ts`，policy=`auto`，toolKind=`file_change`
- **输入**：`markdown`、`operation`（draft/refine）、`source_request`、`title`、`plan_id`、`plan_relative_path`。
- **细节**：`shouldAdvertise` 只在 Plan 模式或有 guiPlan 时广告。两种解析：① **保留路径模式**（renderer 提供 guiPlan）严格校验，只能写 `.kunsdd/plan` 下 Markdown；② **自由模式**按 title/source_request 派生文件名（保留 CJK）防冲突。写入经 `canWritePath` + `withFileMutationQueue` + **临时文件 + 原子 rename**，返回 SHA256 短哈希与字节数。

### 26. todo_list / todo_write（任务清单）

- **标识/文件**：`todo-tools.ts`，policy=`auto`（依赖 ThreadService）
- **细节**：`todo_list` 读本线程进度；`todo_write` 全量替换语义（每条 content/status，可附 source 计划溯源），最多 200 条，强制至多一个 in_progress。

### 27. get_goal / create_goal / update_goal（目标管理）

- **标识/文件**：`goal-tools.ts`，policy=`auto`
- **细节**：`get_goal` 返回目标 + token 预算/已用/剩余；`create_goal` 仅在明确要求时创建（已存在报错，可设 token_budget）；`update_goal` 只能置 complete/blocked，不能用于暂停/恢复/限额。

## 六、扩展 Provider

### 28. mcp-tool-provider（MCP 服务器接入）

- **文件**：`mcp-tool-provider.ts`，`kind='mcp'`
- **细节**：连接 stdio/streamable-http/sse 三种传输；**并行连接** + 启动超时 + 失败后台重连；工具命名 `mcp_<serverId>_<toolName>`；**审批策略派生** `policyFromAnnotations`（readOnly→auto、destructive→on-request、openWorld→untrusted）；信任与可见性（`trustScope` user/workspace、`workspaceRoots`）两端校验；**两种暴露形态**：工具少时直接广告每个 `mcp:<serverId>` Provider，工具达 `autoThresholdToolCount` 或 mode=search 时切换为搜索模式（仅广告 `mcp_search` 系列）。

### 29. mcp-tool-search（MCP 工具动态搜索注册）

- **文件**：`mcp-tool-search.ts`，id=`mcp:search`
- **元工具**：`mcp_search`（auto，按自然语言/服务器/动作/参数搜，返回 topK）、`mcp_describe`（auto，返回完整 schema）、`mcp_call`（on-request，按 id+JSON 实际调用）、`mcp_refresh_catalog`（auto，刷新重建索引报告指纹/漂移）。
- **检索机制**：本地 **BM25 索引** + 关键词加权（精确字段权重 5、动作词 3、参数词 2）；中英文分词（拉丁按 `_-` 拆，汉字 2–4 gram）；`ACTION_SYNONYMS` 中英动作同义扩展；按 minScore 过滤排序。`availableRecords` 单点过滤被 `blockedProviderIds` 拦截的服务器。

### 30. skill-tool-provider（技能加载）

- **文件**：`skill-tool-provider.ts`，id=`skill`
- **细节**：提供 `load_skill`（auto），按 skill_id 主动拉取完整 SKILL.md + 元数据 + 工具约束；技能禁用或无技能时不注册（保持工具目录指纹不变）。

### 31. memory-tool-provider（长期记忆）

- **文件**：`memory-tool-provider.ts`，id=`memory`
- **工具（均 on-request）**：`memory_create`（须用户批准，scope user/workspace/project）、`memory_update`、`memory_delete`（墓碑删除）。无 MemoryStore 不注册。

### 32. delegation-tool-provider（子代理委派）

- **文件**：`delegation-tool-provider.ts`，id=`delegation`
- **工具**：`delegate_task`（auto），参数 `label`（2–4 词）、`prompt`、`workspace`、`model`、`profile`、`detach`。子代理默认按运行时 `defaultToolPolicy`；并行调用排队；`onStart` 在子 id 生成时推送 running 以便 GUI 实时打开子会话。

### 33. web-tool-provider（联网获取与搜索）

- **文件**：`web-tool-provider.ts`，id=`web`
- **工具（均 untrusted）**：`web_fetch`（仅 http/https、域名白/黑名单、`max_bytes` 上限默认 1MB 下限 4096、内置 HTML→纯文本抽取、返回 sources/citations）、`web_search`（limit 默认 5 上限 10）。默认 `FetchWebProvider`（超时 15s）。

### 34. image-gen-tool-provider（图片生成）

- **文件**：`image-gen-tool-provider.ts`，id=`imageGen`，`kind='image'`
- **工具**：`generate_image`（untrusted），参数 prompt、aspect_ratio、image_size、reference_image_paths（工作区内，受 maxReferenceImages 限）。有参考图走 `/images/edits` 否则 `/images/generations`；每次只生成一张存盘工作区，尽量生成内联预览附件。

### 35. media-gen-tool-provider（语音/音乐/视频生成）

- **文件**：`media-gen-tool-provider.ts`，三个独立 Provider：`speechGen`/`musicGen`（audio）、`videoGen`（video）
- **工具（均 untrusted）**：`generate_speech`（text/voice/style/format）、`generate_music`（prompt/lyrics/instrumental/reference_audio_url/format）、`generate_video`（prompt/resolution/首尾帧图）。统一经 `writeGeneratedMediaFile` 存盘，返回 files + telemetry。

### 36. computer-use-tool-provider（桌面操控）

- **文件**：`computer-use-tool-provider.ts`，id=`computerUse`，`kind='gui'`
- **工具**：`computer_use`（on-request，command_execution）。
- **动作集**：screenshot/cursor_position/mouse_move/left_click/right_click/middle_click/double_click/left_click_drag/scroll/type/key/wait（坐标基于最近截图像素空间）。
- **权限限制**：仅能力 enabled + mode≠off + 后端就绪才注册；`mode==='auto'` 还要求视觉模型才广告；**每 turn 动作预算** `maxActionsPerTurn`（超限报 action_budget_exhausted）；macOS 需屏幕录制 + 辅助功能权限；**computer_use 绝不进 baseToolProviders**（不可委派子代理）。

## 七、工具注册与能力发现机制

装配中心 `kun/src/server/runtime-factory.ts`：

1. **基础 Provider 集合 `baseToolProviders`**（主、子代理共享）：builtin（默认本地工具 + `withBackgroundShellTools` 追加 background_shell）、MCP（直连或 `mcp:search`）、web、memory、skill、image/speech/music/video。**刻意排除 computer_use**。
2. **子代理 registry `childRegistry`**：仅用 baseToolProviders，配 childToolHost（开 readTracker 与 hooks），供 DelegationRuntime 子代理执行，工具策略另由 delegation `toolPolicy` 收窄。
3. **主 registry `registry`** = baseToolProviders + computerUse（仅顶层）+ goal + todo + delegation 工具。
4. **能力清单与诊断**：`buildRuntimeCapabilityManifest` 汇总各能力 available/reason，供 GUI 展示排障。
5. **后台动态注册**：MCP 服务器晚连成功时把新 Provider 同时注册进主/子 registry。
6. **运行时能力发现链路**：模型每个 turn 经 `toolHost.listTools(context)` 拿可见工具（逐层过滤），调用时 `toolHost.execute` 经完整闸门管线。「广告层 + 执行层双重门禁 + 多层闸门」是工具系统安全与可控性的核心。
